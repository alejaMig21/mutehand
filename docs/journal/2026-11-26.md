### 01:54 · problem · Nine simulated users agree: the editor is bad

Nine personas used an isolated copy of the editor (fake desktop, fake scheduler). Scores for the interface: child 2, casual 3,
accessibility 3, engineer 3, QA 3, chaos 3, UI designer 4, UX designer 4, and all eight said "bad" (the harsher "awful" was
offered and nobody chose it). The attacker judged the rules, not the looks: "good". None was told what the person thought.
The worst: button labels at 1.05:1 contrast, "New flow" then "Save" overwriting another flow, "Run flow" executing the stored
version instead of the screen, runs lost after a reload or one failed request, and no way to wire two nodes with a keyboard.

**Why it matters:** the earlier browser tests passed while the person could not see the Restore button.
**Evidence:** `assets/2026-11-26-steps-before.png` · `tests/test_editor_safety_e2e.py`
**In their words:** "el ui del proyecto es abrumadoramente horroroso. cada pantalla es peor que la anterior."

### 01:54 · milestone · The defects the market test found are fixed

Each was reproduced as a failing test first. The editor now asks before replacing or discarding a flow, runs what is on the
screen, follows runs by flow and survives reloads, speaks plain words, styles every control, and works from the keyboard.
647 tests and 44 browser tests pass. Restore also failed for every step whose name had a space. The visual identity (type
scale, spacing, palette, screen structure) was not redesigned: that waits for the person's taste.

**Why it matters:** saved work and running automations can be trusted again.
**Evidence:** `web/src/Editor.jsx` · `web/src/useRuns.js` · `src/workflow_factory/api.py` · `assets/2026-11-26-steps-after.png`

### 02:29 · problem · Three engine rules named one app

The Excel lesson had put `app is Excel` branches in the engine. They are gone: a new step action, `select` (click, then Escape),
carries what a cell needs, and a value write is refused for any control with the role `cell`. No file under `src` names Excel.
652 tests and 44 browser tests pass. The rule is now written in the user-wide agent instructions.

**Why it matters:** what the engine learns from one app must hold for the next one.
**Evidence:** `src/workflow_factory/tutor.py` · `src/workflow_factory/agent_desktop.py` · `docs/agents/tutor.md`
**In their words:** "espero que no hayan sido parhes ni fixes sesgados a Excel."

### 03:37 · pivot · The editor has to be thought through again

Explaining the states made the screen heavier without telling a newcomer what to do next, and a flat list of steps will not
survive many apps. This replaces the 02:08 decision to keep the editor as it is. No code until the direction is agreed.

**Why it matters:** the problem is what the screens show, not how they look.
**Evidence:** `assets/2026-11-26-steps-why.png`
**In their words:** "yo ya tengo una edad y no entiendo" / "creo que al editor completo hay que darle una vuelta y pensarlo mejor."

### 04:24 · problem · Non-technical users still cannot find their way

Three personas with no vocabulary and only pictures to act on: casual 3 ("bad"), child 4 ("bad"), elephant 7 ("good", judged on
whether things survive). The casual user finished 3 of 6 chores and could not get past the first day, fix a failed chore or make
one run every morning. The labels On trial, Rejected and Needs a re-check left them with nothing to do. Fixed now: lists that
took 1.3 s with 270 steps take 0.04 s, dropped nodes stay put, notices no longer move the screen, a schedule takes the chosen
flow's program, typed answers and the open flow survive. Open: what the screens should show at all. 656 tests and 53 browser
tests pass.

**Why it matters:** the people who would use the product cannot use it without help.
**Evidence:** `assets/2026-11-26-floating-notice.png`
**In their words:** "hazle caso a esas personas porque son los que pueden llevar de la mano el software a buen puerto."

### 05:05 · problem · A review before committing found engine and editor defects

Two fresh reviewers read the uncommitted work. The worst: a control present in two windows of an app was taken from whichever
window came first, so a run could act on the wrong document. It now stops. Also fixed: a selection could press Escape after the
emergency stop, repeated nodes hid a changed screen from the history, a number that is not finite made a flow unopenable, and
"Connect them in order" built flows that could not be saved. The live Excel check of these engine changes has not been run.

**Why it matters:** an arbitrary choice between windows is a silent write to the wrong place.
**Evidence:** `src/workflow_factory/agent_desktop.py` · `tests/test_agent_desktop_adapter.py` · `tests/test_api_editing.py`
**In their words:** "commiteá"
