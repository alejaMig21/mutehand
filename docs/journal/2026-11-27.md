### 12:00 · problem · Three non-technical personas found 13 defects in the finished build

A casual user, a child and an "elephant" (who taps everything) tried first-day, everyday and many-apps data through
`tests/acceptance_server.py`, with screenshots only. They could not find "Take back", tapped dead action chips, saw the list
jump, lost a deleted chore with no way back after a reload, saw "HTTP 414" after a long paste, and a run shrank the canvas
to half. Each was fixed with a browser test and replayed for the persona that found it. One 500 after idle was traced to a
harness folder deleted by a cleanup, not to the product; the server now says so and prints a traceback on any 500.

**Why it matters:** passing tests had missed all of them; only a person with no vocabulary found them.
**Evidence:** `.scratch/editor-rethink/acceptance.md` · `tests/test_acceptance_fixes_e2e.py`

### 12:00 · decision · "Close the program" moved into a More menu

A child and a casual user closed the program by accident. The person pointed out a tab can be closed by the browser, but the
button also stops the local server, so it stays, one step away from the tabs. The other open points (reject by hand, orphan
daily tasks, last-write-wins renames, no local draft, trash never purged, same-title chores) were all left as they are, to be
re-checked in the next market test.

**Why it matters:** a rare, final action no longer sits where a tap lands by accident.
**In their words:** "un boton cerrar en un sitio web es directamente estupido porque las pestañas de un navegador se pueden cerrar."
