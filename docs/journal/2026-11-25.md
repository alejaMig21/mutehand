### 13:00 · surprise · Accessibility writes steal the foreground window

Two windows driven in parallel had no crossed values and no errors, but `click` and `set-value` took the
foreground window even in headless mode. The engine had assumed accessibility actions need no physical
input. The person chose to serialise every acting node.

**Why it matters:** "no mouse" did not mean "not in the person's way".
**Evidence:** commits `c99fb02`, `5873dfb` · `docs/research/20-parallel-accessibility-actions.md`
**In their words:** "opción 1"

### 15:00 · problem · A live test overwrote text in the person's Notepad

I launched Notepad for a test, but its process pre-dated the session and held the person's tabs. I wrote
into the selected tab and it was not recoverable. Cause: I did not check whether the app already ran
before acting. Since then every live test checks process age first and uses only windows I create myself.

**Why it matters:** the one real harm of the session, and the origin of the "own windows only" rule.
**Evidence:** engram `preference/never-touch-users-open-apps` · `docs/research/20-parallel-accessibility-actions.md`
**In their words:** "espero que de ya estes activando la skill de memoria porque cometiste un error digno de dejar de pagar suscripcion."
